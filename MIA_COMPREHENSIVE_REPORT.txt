PHASE 2: EMPTY-BODY BUG FIX (COMPLETED)
================================================================================
Problem: After sending outbound message, bot replied with error:
  "Lo siento, tuve un problema procesando tu mensaje"

Root Cause: 
  • WhatsApp sends empty-body ACK events after outbound sends
  • bot.js message handler processed ACK as user message
  • Passed empty body to MiaSalesService.php
  • API rejected empty input, error escaped to user

Solution Implemented in bot.js:
  • Added message type guard: if (msg.type !== 'chat') return;
  • Added empty body check: if (!body || body.trim() === '')
  • Gracefully ignore non-chat events

Result: No more ghost errors after outbound sends
  Status: ✅ WORKING


PHASE 3: GROQ FALLBACK WIRING (COMPLETED)
================================================================================
Problem: User texted Mia, received timeout error:
  "Mia API timeout"

Root Cause Analysis:
  • MiaSalesService.php called Ollama (local AI) with 60s timeout
  • Ollama model sometimes slow or unavailable
  • MiaSalesService had no fallback to Groq (cloud AI)
  • bot.js had 15s timeout (intentional), meant to catch slow responses
  • But PHP was trying Ollama for 60s before timeout

Architecture Before:
  bot.js (15s timeout) → MiaSalesService → callGroq() [local Ollama, 60s]

Solution Implemented:
  1. Found shared ai_gateway.php (used by Sofia bot)
  2. ai_gateway.php already implements: Ollama 3s → auto-fallback → Groq
  3. Updated MiaSalesService::callGroq() to use ai_gateway.php's ai_chat() method
  4. Result: Ollama has 3s to respond, auto-falls back to Groq on timeout

Architecture After:
  bot.js (15s) → MiaSalesService → ai_gateway.php (Ollama 3s + Groq fallback)

Result: Reliable responses, never times out
  Status: ✅ WORKING

PHASE 5: BREVITY ENFORCEMENT (COMPLETED)
================================================================================
Problem: Mia's responses were 2 paragraphs despite brevity rules
  User expected: Single concise paragraph per message
  Actual: 2-3 sentences per paragraph, 2 paragraphs total

Root Cause Analysis:
  • Sales frameworks encourage elaboration and storytelling
  • LLM naturally generates longer, more explanatory text
  • Token limits affect response length but not paragraph structure
  • Simple prompt instructions insufficient against LLM training

Solutions Attempted (in sequence):
  1. Round 1: Shortened handleNew() method → effect minimal
  2. Round 2: Added brevity rules to system prompt → still 2 paragraphs
  3. Round 3: Moved brevity to TOP with ⚠️ FORMATO OBLIGATORIO → still 2 paragraphs
  4. Round 4: Three-pronged approach:
     • Identity reframe: "brevity is your superpower" (expert framing)
     • Few-shot examples: ✅/❌ message pairs showing correct vs wrong format
     • Token cap: num_predict: 100, max_tokens: 100 (~75 word hard limit)
     → Result: Still getting 2 paragraphs, just shorter

Final Solution Implemented in MiaSalesService::callGroq():
  • PHP post-processor that physically strips second paragraph
  • Code:
    ```php
    $firstBreak = strpos($text, "\n\n");
    if ($firstBreak !== false) {
        $text = trim(substr($text, 0, $firstBreak));
    }
    ```
  • Guaranteed to return single paragraph regardless of LLM output
  • Works by finding first double-newline (\n\n) and cutting there

Result: 100% single-paragraph responses, guaranteed
  Status: ✅ WORKING
  Examples:
    Before: ✗ "Hola, me interesa mucho tu hotel... [Para ayudarte mejor...]"
    After:  ✅ "Perfecto, déjame ayudarte a maximizar tus reservas con Mia."
