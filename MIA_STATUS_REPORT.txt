1. WHAT IS MIA?
--------------------------------------------------------------------------------
Mia is an AI-powered WhatsApp sales bot for AiniDesk — a B2B SaaS that sells
AI receptionist software to hotels and small hospitality businesses.

Mia lives on WhatsApp. When a potential customer texts the Mia number, the bot
receives the message, passes it to a PHP AI service, and sends back a sales reply.
Her goal: qualify leads and capture name + email for follow-up/demo booking.

3. STATE MACHINE — MIA'S CONVERSATION FLOW
--------------------------------------------------------------------------------

new → intro → qualifying_size → qualifying_method → qualifying_pain
    → roi_pitch → demo → benefits → closing
    → collecting_name → collecting_email → captured

State descriptions:
  new              - First message ever received
  intro            - Mia introduces herself, asks about business type
  qualifying_size  - Asks how many rooms/staff
  qualifying_method- Asks current booking/reception method
  qualifying_pain  - Asks about biggest pain point
  roi_pitch        - Presents ROI/value based on pain
  demo             - Offers to show product
  benefits         - Explains key features
  closing          - Asks for commitment / trial
  collecting_name  - Captures lead's name
  collecting_email - Captures lead's email
  captured         - Lead fully captured, hands off to human team

Database: MySQL table "mia_sales_sessions" on VPS
  Columns: phone, state, business_name, contact_name, email,
           business_type, room_count, current_method, pain_point,
           conv_history (full JSON history for AI context), timestamps

4. SALES INTELLIGENCE — FRAMEWORKS BUILT INTO MIA
--------------------------------------------------------------------------------
MiaSalesService.php system prompt encodes these proven sales frameworks:

  - Challenger Sale: teach → tailor → take control of conversation
  - SPIN Selling: Situation → Problem → Implication → Need-Payoff questions
  - Loss Aversion: frame pain/loss 2x more than gain (prospect psychology)
  - Micro-commitments: progressive yes ladder before asking for the big yes
  - Feel/Felt/Found: objection handling ("I understand... others felt... they found...")
  - Choice Close: never yes/no → always option A or option B
  - Social Proof: reference similar businesses that succeeded
  - Future Pacing: help prospect imagine life after the product
  - Cinematic Demo: paint vivid picture, don't just list features

5. BREVITY ENFORCEMENT — HOW WE KEEP MIA SHORT
--------------------------------------------------------------------------------
Problem: LLMs naturally write long, formal responses. WhatsApp texting requires
short, human, conversational messages.

Three-layer solution (all active):

  Layer 1 — Identity reframe in system prompt
    "Brevity is your superpower. The best salespeople speak LESS, not more."
    Pascal quote framing: short = smart. Long = lazy.
    ✅/❌ few-shot examples showing correct vs. wrong message style.

  Layer 2 — Token cap
    num_predict: 100 (Ollama) + max_tokens: 100 (Groq)
    Equivalent to ~75 words — tight but enough for one punchy sales message.

  Layer 3 — PHP post-processor (definitive hard cut)
    After AI responds, PHP finds the first blank line (\n\n) and discards
    everything after it. Physically impossible to show 2 paragraphs.
    Code in callGroq() method:
      $firstBreak = strpos($text, "\n\n");
      if ($firstBreak !== false) {
          $text = trim(substr($text, 0, $firstBreak));
      }
